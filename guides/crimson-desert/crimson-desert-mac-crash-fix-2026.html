What Pearl Abyss Officially Acknowledges on Mac

Mac coverage for Crimson Desert is thin everywhere, and most of what exists is guesswork copied between aggregator sites. This page works from a different source: Pearl Abyss's own Known Issues list for Crimson Desert, updated 1 August 2026. That document names three Mac-specific problems outright, which means we are not asking you to trust a forum thread — we are asking you to trust the developer's own bug tracker.

The three officially listed items are: (1) enabling the MetalFX Denoising Upscaler causes the client to crash, with the official remedy being to delete the User Engine Option file; (2) when playing with keyboard and mouse at certain resolutions, the placement point for furniture does not line up with the cursor; and (3) the colour blindness filter does not apply to UI elements, only to the rendered game scene.

The current client is version 1.000.484 (2.00.00, released 25 August 2026). As of that build these three items are still on the official Known Issues list — they are not listed among the fixes that shipped in patch 1.18.02 on 17 August 2026. We re-check the list each patch cycle and update this page, so if you are reading this months from now, treat the status line here as the current one.

Why this matters: knowing a bug is officially confirmed changes what you do next. For a confirmed bug you stop troubleshooting your own machine and start applying the official workaround, because no amount of driver reinstalling will fix a defect the developer has already acknowledged.

Issue 1 — MetalFX Denoising Upscaler Crash

This is the one that actually costs people playtime. MetalFX is Apple's upscaling family, and the denoising upscaler is the aggressive variant that reconstructs a higher-resolution frame from a lower-resolution one while cleaning up noise. Enabling it in Crimson Desert triggers a crash — officially confirmed, not a hardware defect on your end.

How to recognise it

  • The crash is repeatable and tied to the setting, not random. If your game runs for hours and then dies once, this is not your bug.
  • It happens on or immediately after enabling the option, or on the first frame the upscaler actually has work to do.
  • Because the setting is written to your User Engine Option file, relaunching re-applies it. That is the practical reason the official workaround is file-level rather than menu-level: if the client dies before you can navigate back and switch the option off, the menu route is closed to you.

The fix

1

Quit the game completely

Close the window and confirm the process is gone. If the client is hung on the crash, force-quit it. Do not proceed while the game is still running, or it may rewrite the file you are about to delete.

2

Back up the User Engine Option file

Copy it somewhere safe before touching it — Desktop is fine. Section 6 covers exactly how to find it and what else to copy while you are there.

3

Delete it (or move it out of the folder)

Moving it to a folder on your Desktop is safer than deleting outright: same result for the game, fully reversible for you. This is the remedy Pearl Abyss itself specifies.

4

Relaunch and let the client rebuild defaults

The game regenerates a fresh options file on startup. Everything will be back at default values, which means the MetalFX Denoising Upscaler is off.

5

Verify, then re-tune everything except that one toggle

Load a save, move the camera, and cross at least one area boundary. If it holds, you are clear. Re-apply your other display settings one at a time so that if something else crashes, you know exactly which setting did it.

Expect a full settings reset: the User Engine Option file holds your engine and graphics configuration as a whole, not just the upscaler toggle. Deleting it resets all of those options, so budget a few minutes to put your display, quality and control preferences back the way you like them.

Issue 2 — Furniture Placement Cursor Offset

The official wording is that when using keyboard and mouse at certain resolutions, the point where furniture is placed does not match the cursor position. In practice that means housing and camp decoration becomes a guessing game: you aim at a spot, commit, and the item appears somewhere else by a consistent-looking margin.

How to recognise it

  • It is placement-mode specific. Combat, dialogue and general navigation feel normal; only the placement preview is wrong.
  • The mismatch is resolution-dependent. Players report it appearing at some resolutions and not others, and the size of the gap changing when they switch resolution — which is the tell that separates this bug from a general "the placement system is clunky" complaint.
  • It is tied to mouse and keyboard input. The official note scopes it that way, so a connected controller is a legitimate workaround rather than a superstitious one.

The fix

Pearl Abyss lists this as a known issue without a menu-level remedy, so what you have are workarounds that avoid the broken code path:

Option A — Change your resolution

Since the defect is resolution-dependent, switching to a different resolution moves you out of the affected case. Try your display's native resolution first, then one step down. Re-test placement after each change rather than assuming the first switch worked.

Option B — Place with a gamepad

Because the official note scopes the bug to mouse and keyboard, connecting a controller and using it for placement mode specifically gets you correct alignment while you keep mouse and keyboard for everything else. This is the least disruptive workaround if you own a pad.

Option C — Defer the decorating

If neither of the above is practical, park your furnishing plans. This is a confirmed defect sitting on a public list, which makes it a reasonable candidate for a future fix — unlike an undocumented quirk that nobody at Pearl Abyss knows about.

Verify before you commit: place one cheap, easily-moved item as a test. If it lands precisely under the cursor, your workaround is working. Do not spend twenty minutes arranging a room before you have run that test.

Issue 3 — Colour Blindness Filters Skip the UI

Crimson Desert ships colour blindness filters, and they do work — on the game world. What they do not cover, per the official Known Issues list, is UI elements. Menus, HUD elements and interface text keep their original colours while the scene behind them shifts. For players who rely on the filter to read threat indicators or loot rarity cues that live in the interface, that gap is the whole problem.

How to recognise it

  • Turning the filter on produces an obvious change in the 3D scene only. If you open a menu and the colours look untouched while the world behind it has shifted, you are looking at this exact issue.
  • The behaviour is consistent across all UI surfaces, not intermittent. A filter that works on some menus and not others would be something else.
  • The in-game filter strength slider does not close the gap — it intensifies the scene effect and leaves the UI alone.

The fix

The reliable workaround is to move the filtering one level up, to macOS itself. System-level colour filters are applied to everything the display outputs, including a full-screen game and its interface.

1

Open the macOS accessibility display settings

Go to System Settings → Accessibility → Display → Color Filters. If you are on an older macOS release the same pane lives under System Preferences → Accessibility → Display. The exact wording varies slightly between macOS versions.

2

Enable Color Filters and pick your type

Choose the filter that matches your need (the same categories the game offers) and adjust intensity with the slider.

3

Turn the in-game filter off and verify on a menu

Running both stacks two filters on the scene and one on the UI, which usually looks wrong — let the system filter handle everything uniformly. Then open your inventory or map: if the interface colours shift along with the scene, you are done.

Beyond colour handling, if dense interface text is part of the problem, raise UI scale and contrast in the game's display options where those are offered. For a broader look at what the options menu can and cannot do for readability, see our Settings Guide.

Back Up the User Engine Option File Before You Delete It

Deleting a file a support document tells you to delete is fine. Deleting it without a copy is how a five-minute fix becomes an afternoon of re-tuning settings you had carefully dialled in. Two minutes of copying first.

How to find it

The file is part of Crimson Desert's user data on your Mac, alongside your saves. Its exact folder path depends on how and where the client was installed, and can shift between client versions — so rather than trusting a hardcoded path, locate it directly:

  • Open the folder where Crimson Desert stores its user data for your installation and look for a configuration file named along the lines of User Engine Option — that is the name Pearl Abyss uses in its own instructions. If browsing fails, use Finder's search within that folder or Spotlight and match on the file name.
  • When in doubt, take a copy of the entire user data folder rather than gambling on one file.

What to copy, and what is safe

  • User Engine Option file — copy it first, always. Losing it costs your graphics, display and engine settings.
  • Progression save data — back it up if you can locate it, though the official workaround does not target it.
  • Cloud save state — confirm it has synced so you have a rollback option if anything local goes wrong.
Scope check: the official instruction is to delete the User Engine Option file — an options file, not a save file. Deleting it resets your settings, not your progress. That said, if you are touching files in a folder that also holds your saves, copy the whole folder first. Confirm your cloud save has synced before you start anything.

Living With the Mac Port on Apple Silicon

We are not going to quote frame rates for specific M-series chips. We have not benchmarked them, Pearl Abyss has not published per-chip numbers, and any site giving you a confident "M3 Pro gets X fps in Pywel" is inventing it. Here is what can be said honestly.

What the Mac build is working with

The Mac client runs on Metal, and MetalFX upscaling is the main lever you have for trading internal resolution for smoothness. That is precisely why the crash issue stings: the setting you would most want to reach for on an integrated-GPU Mac is the one setting that is currently off the table. Until it is fixed, your realistic levers are internal resolution, the non-denoising upscaler path if one is offered, and the usual quality presets.

Practical expectations

Expect to run at a reduced internal resolution, since upscaling is doing the heavy lifting and the denoising variant is unavailable. Favour stable frame delivery over peak settings — a locked, consistent frame rate beats a higher average that stutters through combat. And do not assume Windows tuning advice transfers: most Crimson Desert performance guides are written for NVIDIA and AMD hardware, where the option names may match but the tradeoffs do not.

For the general settings walkthrough, start with our Best Settings for Performance guide and cross-check against the platform notes in our Platform Comparison. The 2.0 update changed several graphics-adjacent defaults, so also skim our 2.0 Enhanced Update Guide before you settle on a configuration.

If your crash is not the MetalFX one

Work down this list in order. It is generic on purpose — these steps are safe regardless of what is actually wrong, and they rule out the common causes before you spend time on anything exotic.

General triage, in order

  1. Confirm your client version. Check that you are on 1.000.484 (2.00.00) or later — an outdated client crashes for reasons that are already fixed.
  2. Verify game files. Use your storefront's verify-integrity function; a corrupted install is the most common cause of crashes that survive a settings reset.
  3. Update macOS. Metal and MetalFX behaviour is tied to the OS, so install pending system updates before assuming the game is at fault.
  4. Re-add settings one at a time. You are already at defaults after deleting the options file. Change one thing, play, repeat — slow, but the only reliable way to find a setting-specific crash.
  5. Report it with reproduction steps. Note your Mac model, macOS version, client version and exact steps. Reproducible reports get triaged; "it crashes sometimes" does not.

If you have hit any of the broader crash patterns rather than a Mac-specific one, our Crash Fix Guide covers the platform-agnostic cases.

FAQ

Is the MetalFX crash an officially confirmed issue?

Yes. Pearl Abyss's Known Issues list for Crimson Desert, updated 1 August 2026, names it directly and specifies deleting the User Engine Option file as the remedy. This is not a community theory.

Will deleting the User Engine Option file delete my save?

It should not — the official instruction targets an options file, not your progression saves. The two live in your user data folder, though, so copy the whole folder before deleting anything and confirm your cloud save has synced.

What exactly do I lose by deleting that file?

Your engine and graphics configuration: resolution, quality presets, display mode and anything else stored there. The game rebuilds a default version on next launch. Your campaign progress is unaffected.

Can I just turn the upscaler back off in the menu instead?

If the client stays alive long enough for you to reach the menu, yes — that is the cleaner route. The file-deletion method exists for the case where the crash happens before you can navigate back and undo the setting.

Why does my furniture land away from the cursor?

It is an officially listed issue: with keyboard and mouse at certain resolutions, the placement point does not line up with the cursor. Change resolution or place with a gamepad.

Is the cursor offset a mouse sensitivity or DPI problem?

No. The official note attributes it to resolution, and the tell is that the gap changes when you change resolution rather than when you change sensitivity. Adjusting DPI will not close it.

Do the colour blindness filters work at all?

Yes, on the rendered game scene. The officially listed limitation is that they do not apply to UI elements such as menus and HUD. Use macOS system colour filters if you need the interface covered too.

Should I run the in-game filter and the macOS filter together?

Usually not. Stacking them double-filters the scene while the UI gets one pass, which looks inconsistent. Pick the system filter if you need uniform coverage.

Will these three issues be fixed?

We cannot promise that. What we can say is that all three are on a public list maintained by Pearl Abyss, which is a much better position than an undocumented bug nobody has acknowledged. We update this page each patch cycle.

Does any of this affect the Windows version?

No — all three are Mac-specific entries. Windows players dealing with visual corruption should look at our GPU Driver Guide instead.
