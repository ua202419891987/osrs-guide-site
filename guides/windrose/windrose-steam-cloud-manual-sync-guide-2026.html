Why You Have to Sync Windrose by Hand

Windrose saves are not a tidy single file. They are a RocksDB database, which means the save is a directory of many small interlocking files rather than one blob you can copy. That structure is good for the game and awkward for sync engines: if Steam Cloud decides a directory is unchanged, or partially syncs it, or loses its place mid-upload, you get a state where the cloud copy and the local copy disagree and nothing tells you which one is newer.

The symptoms are familiar if you have been burned by it: you boot up on a different machine and your world is hours behind, or the game hangs on the loading screen because it is waiting on cloud data, or a save that was definitely there last night is simply absent today.

Steam does expose a manual sync path — it is just buried in the Steam console rather than in any menu. The official Windrose FAQ documents the exact commands, and this guide reproduces them so you can copy and paste.

Before you start: close the game completely. Running a sync while Windrose has the save files open is the fastest way to produce a half-written cloud copy. Exit to desktop, confirm the process is gone, then sync.

Upload or Download? Get This Right First

There are two commands and they do opposite things. Picking the wrong one does not damage your disk, but it will overwrite the copy you wanted. Read this table before you type anything.

CommandDirectionUse it when
cloud_sync_up 3041230Local → CloudYou just played on this machine and want the cloud updated to match
cloud_sync_down 3041230Cloud → LocalThis machine's local save is missing, older, or corrupted

The number 3041230 is Windrose's Steam App ID. It is what tells Steam which game's cloud storage you mean, and it is the same for the up and down commands.

The one rule that prevents disasters: cloud_sync_down overwrites your local save with the cloud copy. If your local save is the good one and the cloud is stale, running "down" destroys it. Always confirm which side holds the progress you want to keep before you press enter.

Quick decision rule

Played here last? Run up.
Playing here for the first time, or this machine's save is wrong? Run down.
Not sure which copy is newer? Open the local folder and check file timestamps against the last time you played, then decide.

If you are on a brand-new machine with no local save at all, "down" is always safe — there is nothing local to lose.

The Full Command Sequence

This is the official procedure from the Windrose FAQ, in order. Follow the sequence rather than cherry-picking steps; the logging parts are what let you confirm it actually worked.

1

Close the game

Exit Windrose fully. Do not leave it running in the background or minimised to the tray.

2

Open the Steam console

Press Win + R, type the following, and press Enter:

steam://open/console

Steam will open a window with an extra Console tab alongside your library.

3

Turn on verbose logging

Type this into the console and press Enter. It raises the log level so you can actually see what the sync is doing:

set_spew_level 4 4
4

Run the sync you need

To push your local save up to the cloud:

cloud_sync_up 3041230

To pull the cloud save down onto this machine:

cloud_sync_down 3041230

Run one or the other, not both. Wait for it to finish — the console will scroll a lot of output, and you want to let it settle before judging the result.

5

Check the log for the backup files

Scroll the console output and confirm the RocksDB V2 backup files synced successfully. You are looking for those specific backup files being reported as transferred, not just a generic "sync complete" line. Details in the next section.

6

Turn the logging back down

Once you are satisfied, reset the spew level so Steam stops writing enormous logs:

set_spew_level 0 0
Do not skip step 6. Leaving the log level at 4 4 makes Steam write a lot of noise to disk indefinitely, which is exactly the kind of thing that quietly slows a machine down over weeks.

Reading the Log to Confirm It Worked

The whole point of set_spew_level 4 4 is verification. Without it you get a silent success-or-failure and no way to tell which happened.

In the console output, look for entries naming files under the RocksDB V2 backups path. What you want to see is those backup files being uploaded or downloaded as part of the sync — that is the signal the save database travelled, not just some unrelated config file.

If you see the backup files listed with successful transfer lines, you are done. If the sync reports success but no RocksDB V2 backup files appear anywhere in the output, treat it as a failed sync and investigate before you trust the cloud copy.

Local path to verify by hand

You can confirm the result on disk at:

C:\Users\%username%\AppData\Local\R5\Saved\SaveProfiles\%your_Steam_ID%\RocksDB_v2_Backups

Two substitutions: %username% is your Windows account name, and %your_Steam_ID% is your numeric Steam ID — the folder is named after it, so if you have more than one account that has played Windrose on this PC, make sure you are in the right one. Check the timestamp on the backup files to confirm the sync actually landed.

If you are stuck on a loading screen while the game waits on cloud data, that is a related but distinct problem — see our Loading Screen Steam Cloud Fix.

The Three RocksDB Folders

Inside your save profile folder you will see three similarly named directories. They are not duplicates, and knowing which is which saves you from restoring the wrong thing.

FolderWhat it isShould you touch it?
RocksDBThe legacy save format directoryLeave alone unless a guide tells you otherwise
RocksDB_v2The current live save database the game reads and writes during playThis is your actual world — never delete it
RocksDB_v2_BackupsBackup snapshots of the v2 databaseThis is the recovery source — read-only in practice

The practical takeaway: RocksDB_v2 is where your game lives right now, and RocksDB_v2_Backups is the pool of snapshots you fall back on when something goes wrong. Anything you do manually should be a copy out of the backups folder, never a deletion of either.

Never delete RocksDB or RocksDB_v2 to "clean up." They are not cache. Deleting them removes your world, and the only thing standing between you and total loss is the backups folder.

This matters for cloud sync specifically because it is the RocksDB_v2_Backups files the official procedure tells you to confirm in the log. If only the live database synced and the backups did not, you have a cloud copy with no recovery depth.

Real Scenarios — New PC, Reinstall, Rollback

Moving to a new PC

On the old machine: close the game, run cloud_sync_up 3041230, verify the backup files in the log. On the new machine: install Windrose, launch it once and quit, then run cloud_sync_down 3041230. Launch and your world should be there. Checking the log before you wipe or sell the old machine is the step people skip and regret.

Reinstalling Windows or the game

Before the reinstall, force an up and confirm it. A clean Windows install removes everything under AppData\Local\R5, so the cloud copy is your only safety net. After reinstalling, run down before you start a new world — if you create a fresh world first, you may overwrite the cloud copy with the empty new save.

Rolling back after something broke

If your current save is corrupted or a patch chewed through your world, the recovery path runs through the backups folder rather than through cloud sync. That is a different procedure with its own steps — our Save Backup & Data Recovery Guide covers restoring from RocksDB_v2_Backups and the in-game Data Recovery screen, and Save Loss Recovery covers the wider picture.

Two machines, one world

If you alternate between a desktop and a laptop, get in the habit of running up at the end of every session on whichever machine you just used, and down at the start of a session on the other one. It is mildly annoying and it completely removes the "which machine has my progress" problem.

When Manual Sync Is Not Enough

Forcing a sync fixes disagreement between your local and cloud copies. It does not fix a cloud copy that is itself wrong. If you synced up after your world was already corrupted, the cloud now holds a corrupted save — syncing again will not help, and syncing down will just re-download the damage.

In that situation stop and move to recovery instead. Windrose creates backup snapshots during play and when you exit to the desktop, and those snapshots are your rollback target. The Save Backup & Data Recovery Guide walks the restore path for both local play and dedicated servers.

If the game will not get past the loading screen at all, deal with that first — see Loading Screen Steam Cloud Fix — because a manual sync is not going to rescue a hang.

FAQ

How do I open the Steam console?

Press Win + R, type steam://open/console, and press Enter. Steam gains a Console tab where you type the sync commands.

What is 3041230?

Windrose's Steam App ID. Both cloud_sync_up and cloud_sync_down take it as the argument so Steam knows which game's cloud storage to act on.

Should I use cloud_sync_up or cloud_sync_down?

Use up if you last played on this machine and want the cloud updated. Use down if this machine's save is missing, older, or broken. down overwrites your local save, so be certain first.

Do I need to close the game first?

Yes. Syncing while Windrose has the save files open risks a half-written cloud copy. Exit to desktop before you start.

What does set_spew_level 4 4 do?

It raises Steam's log verbosity so you can see the sync details and confirm the RocksDB V2 backup files transferred. Reset it afterwards with set_spew_level 0 0.

Why should I reset the spew level to 0 0?

Leaving it at 4 4 makes Steam write very large logs continuously, which wastes disk and can slow things down over time.

Where are my Windrose saves stored locally?

C:\Users\%username%\AppData\Local\R5\Saved\SaveProfiles\%your_Steam_ID%\ — the RocksDB_v2_Backups subfolder holds the backup snapshots.

What is the difference between RocksDB, RocksDB_v2 and RocksDB_v2_Backups?

RocksDB is the legacy directory; RocksDB_v2 is your live save database; RocksDB_v2_Backups holds backup snapshots and is what you restore from. Do not delete either of the first two.

The sync said success but my world is still old. What now?

Check whether the RocksDB V2 backup files actually appeared in the log. A generic success line without those files means the save data did not really transfer.

Can I use this to recover a corrupted save?

Not by itself. If your cloud copy is also corrupted, syncing just moves the damage around. Use the backup snapshots and the Data Recovery screen instead — see our Save Backup & Data Recovery Guide.

Does this work for dedicated server saves?

No — dedicated server saves live with the server, not in your Steam Cloud. This procedure is for your local single-player and client saves.

I have two Steam accounts on this PC. Which folder is mine?

The SaveProfiles folder names each subfolder after the numeric Steam ID. Check which ID you are logged in as and open the matching folder.
