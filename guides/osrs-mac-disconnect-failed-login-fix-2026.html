OSRS Mac "Failed to Login" & Random Disconnect Fix 2026 (Apple Silicon & Jagex Launcher)

🆕 NEW

If you play Old School RuneScape on a Mac — especially an Apple Silicon Mac (M1, M2, M3, or M4) — you may hit a "Failed to login" wall, watch the Jagex Launcher hang on a plugin that never loads, or get yanked offline mid-run with no warning. This guide breaks down every Mac-specific cause and gives you a clean, ordered fix flow.

📅 Stage 3 · Mac Client Troubleshooting — Updated July 2026 · 14 min read
🛡️ Level: 1+

⏱️ Quick Verdict — 30-Second Read

  • 📌 Most Mac login failures are not your password. On Apple Silicon the Jagex Launcher can run the wrong CPU architecture under Rosetta, so it hangs before it ever reaches the login servers.
  • 📌 #1 Mac fix: confirm you're on a native arm64 build and remove the macOS quarantine flag with xattr -dr com.apple.quarantine.
  • 📌 "Failed to login" after a password reset? Clear the stale Jagex tokens in Keychain Access — macOS keeps the old session and replays it.
  • 📌 Random disconnects are usually macOS sleep/Wi-Fi power-save or IPv6/DNS, not Jagex. Switch DNS to 1.1.1.1 and disable sleep-on-lid-close.
  • 📌 Plugin "not responding"? Force-quit the stuck java process in Activity Monitor and wipe the launcher cache in ~/Library/Caches.

This guide is the Mac-only companion to our cross-platform troubleshooting. If the mobile login fix didn't get you in, the problem is almost certainly something unique to macOS or Apple Silicon. The good news is that Mac login problems are unusually predictable: they cluster around three root causes that Windows and Linux players essentially never hit.

We'll separate those three root causes — CPU architecture, the Keychain token cache, and the macOS network/sleep behavior — so you don't waste time on generic fixes that don't apply. If you migrated recently, the Jagex migration guide explains why your login path may have changed after a re-link. And when the game freezes rather than failing to log in, pair this page with the world-unavailable disconnect guide, and keep the account security guide open so a recovered session stays protected.

The single most important mindset shift: on a Mac, a "broken game" is almost always a "broken local client." Jagex's servers don't care what operating system you use once the handshake completes. So if your Mac specifically fails while your phone logs in fine, the fault is on the Mac side 99% of the time — and that's good news, because it means every fix lives in your hands, not in a support ticket queue.

1. 🔍 Is It Jagex or Your Mac? Check First

Before you touch a single macOS setting, rule out the server side. The mobile login troubleshooting flow applies to desktop too: if thousands of players across every platform can't log in at once, it's a Jagex outage, not your Mac. Confirm with @JagexSupport on X, the official status page, or a quick glance at r/2007scape. Outages are real and routine — a bot-ban wave, a datacenter failover, or a bad deploy can take login down for minutes or hours.

If the servers are green but your Mac still fails, the problem is local — and Macs have a few failure modes Windows and Linux players almost never see. The biggest one is CPU architecture. Apple's M-series chips are arm64; much of the old RuneScape tooling was built for Intel x86_64 and only runs through Rosetta 2 translation. When the Jagex Launcher or its bundled Java is the wrong flavor, it can hang silently instead of showing an error — which looks exactly like "the game is broken." We cover that in our world-unavailable disconnect guide for the networking half of the problem.

Why a silent hang is the Mac signature

On Windows, a broken Java install usually throws a visible error window. On macOS, a Java process that can't initialize its native display component simply blocks the UI thread and waits forever. You get a spinner, a beachball, or a frozen window with no message. That silence is the tell: it means the client reached a state it can't recover from locally, and the fix is to correct the environment (architecture, cache, tokens) rather than "retry the password." Treating a silent hang as a password problem is the #1 reason Mac players waste an hour before they fix the real thing.

Step 1 — Three 30-second checks

  • Open the official Jagex status channel. Any "Login issues" banner? Wait it out — hammering login can rate-limit your account.
  • Try logging into the OSRS website with the same account. If the website works but the Mac app doesn't, it's 100% client-side on your Mac.
  • Check Activity Monitor (Cmd+Space → "Activity Monitor"). Is a java or "Jagex Launcher" process sitting at 0% CPU or pegged at 100% with no window? That's the hang we fix in Section 4.
💡 The 10-Minute Rule Still Applies

If status confirms maintenance, just wait 10–15 minutes. "Fixing" a client that's fine won't help, and rapid retries during an outage get your IP temporarily throttled. Come back and start from Section 2 once the servers are healthy. A throttled IP can itself look like a "failed to login" even after the servers recover.

2. 🍏 Apple Silicon & Java — Architecture & Java Path

The Jagex Launcher on macOS depends on Java. On an Apple Silicon Mac the single most common "nothing happens" or "stuck on loading plugin" symptom comes from a Java architecture mismatch: an x86_64 (Intel) Java build running under Rosetta, talking to an arm64 launcher, or vice-versa. The mismatch doesn't crash loudly — it just freezes, because the native plugin component never initializes and the UI thread blocks waiting on it.

② Check what Java your Mac is actually using

Open Terminal (Cmd+Space → "Terminal") and run the three commands below. They tell you, in order, which Java builds exist, what architecture your shell reports, and what architecture your default Java binary actually is. The third command is the decisive one — it inspects the binary itself rather than trusting the reported shell.

🖥️ Commands to identify your Java

  • /usr/libexec/java_home -V — lists every installed Java and its architecture. Look for arm64 vs x86_64 in the output.
  • uname -m — should print arm64 on M-series Macs. If you see x86_64, a terminal app is running under Rosetta.
  • file "$(/usr/libexec/java_home)/bin/java" — tells you definitively whether your default Java binary is arm64 or x86_64.

If your default Java is x86_64 and your Mac is Apple Silicon, uninstall the Intel Java and install the arm64 (aarch64) build of Eclipse Temurin / Adoptium (or Azul Zulu for macOS arm64). A native arm64 Java removes the Rosetta translation layer and fixes the silent hang for most M-series players. Don't just "update" the existing Intel Java — you need a different architecture build, not a newer version of the wrong one.

③ Set an explicit JAVA_HOME (and stop Terminal from lying)

Even with the right Java installed, some launchers pick up the wrong one via PATH. Pin it explicitly so the session can't drift to an Intel build:

🔧 Export JAVA_HOME for the session

  • export JAVA_HOME=$(/usr/libexec/java_home -v 17) — forces Java 17 (the version OSRS tooling expects).
  • Launch the Jagex Launcher from that same Terminal window to inherit the variable: open "/Applications/Jagex Launcher.app".
  • To make it permanent, add the export line to ~/.zshrc (the default shell on modern macOS).

Why bother with JAVA_HOME when the launcher "should" find Java itself? Because macOS can have three or four Java builds installed at once — leftovers from old Minecraft launchers, IDEs, and CI tools all pile up. The first one on PATH is not guaranteed to be the arm64 one, and a wrong arch there is exactly the silent-hang bug. Pinning it removes the ambiguity. If you ever see the launcher work from Terminal but fail from Launchpad, a missing JAVA_HOME in the login shell is the usual reason.

⚠️ Don't Mix Rosetta and Native

If Terminal itself runs under Rosetta (check uname -m), every Java it launches will be the wrong arch. Right-click Terminal → Get Info → make sure "Open using Rosetta" is UNCHECKED. A native Terminal + native Java = no translation hang. This single checkbox is the most overlooked fix on M-series Macs.

Native arm64 vs Rosetta — what actually changes

Rosetta 2 is a translation layer, not an emulator, and it's excellent — for most apps you'd never notice. But the Jagex Launcher's plugin loader fetches a small native display component on first run, and that component must match the process architecture. When the Java process is x86_64 inside a Rosetta bubble but the launcher expects arm64, the loader waits on a component that never arrives. The table below summarizes the practical differences so you can recognize which camp you're in.

AspectNative arm64 Javax86_64 Java under Rosetta

3. 🔑 "Failed to Login" — Mac-Specific Fixes

When the launcher does open but rejects your credentials with "Failed to login", and you're sure the password is right, the cause is almost always one of these Mac-specific gremlins — not your account itself. After a password change or a macOS update, account locks from suspicious activity can also kick in, so rule that out if you've recently traveled or used a VPN.

④ Clear stale Jagex tokens from Keychain

macOS Keychain caches your Jagex/login tokens. After a reset or a failed update, the launcher keeps replaying the old token and the server rejects it — even though your new password is correct. The server sees a stale, invalid session and returns "Failed to login" rather than "wrong password," which is why it feels like the password isn't the issue (because it isn't). Fix:

  1. Open Keychain Access (Cmd+Space → "Keychain Access").
  2. Search Jagex and RuneScape.
  3. Delete every matching entry (they regenerate on next successful login).
  4. Restart the Jagex Launcher and log in fresh.

Don't skip the "delete every matching entry" step. Players often delete one and miss a second token, so the launcher replays the surviving stale one and the error returns. Clear all of them in one pass. This is also the fix when login works on your iPhone but not your Mac — the two clients store separate tokens, and only the Mac's are stale.

⑤ Remove the quarantine flag

macOS marks downloaded apps as "quarantined" and Gatekeeper blocks their network calls until you approve. If the launcher was downloaded with a browser that didn't prompt, it can sit quarantined and fail every login silently. The fix is a single Terminal command that strips the quarantine extended attribute:

🧹 One-line un-quarantine

  • sudo xattr -dr com.apple.quarantine "/Applications/Jagex Launcher.app"
  • Also clear it on the game client app if separate: sudo xattr -dr com.apple.quarantine "/Applications/Old School RuneScape.app"
  • Re-open the launcher; Gatekeeper will no longer intercept its connections.

Why does this matter for login specifically? Gatekeeper doesn't just block the app from launching — it can allow the app to open but block its outbound network handshake to the login servers, which produces a "Failed to login" that looks identical to a server-side reject. The quarantine flag is also re-stamped by some macOS updates, so if login breaks again after a system update, re-run this command before anything else.

⑥ Account type still matters on Mac

Just like on mobile, a Jagex account, a Steam-linked account, and a Google/Apple SSO account each need their own button. Typing your email + password for a Steam-linked character always returns "Failed to login" on macOS too. Mirror the login method you use on the website. If you migrated recently, see our Jagex account migration guide for the re-link steps that often get skipped after an email or SSO change.

💡 Clock Skew Breaks 2FA Too

If you reach the 6-digit code step but it's "always wrong", your Mac clock may be off by more than 30 seconds. Go to System Settings → General → Date & Time and enable "Set time and zone automatically". Authenticator codes are time-based; a skewed clock invalidates every one, and the error reads like a credential failure even though the password was fine.

4. 🧩 Plugin "Not Responding" / Unresponsive Launcher

This is the classic Apple Silicon complaint: the launcher opens, the little loading plugin spins forever, and you see a frozen window, a beachball, or a process that never paints a login screen. Here's the recovery order — do it in this sequence, because each step builds on the last.

⑦ Force-quit the stuck process

  1. Cmd+Option+Esc → select "Jagex Launcher" → Force Quit. Or open Activity Monitor and kill the java process directly.
  2. Don't just close the window — a hung java thread keeps the port locked and the next launch collides with it.

The reason you must force-quit rather than close the window: a frozen Java thread often survives a window close and keeps holding the local port the launcher needs. The next launch then fails to bind that port and either hangs again or throws a cryptic "address already in use" error. Always confirm the java process is gone in Activity Monitor before relaunching.

⑧ Wipe the corrupted cache

A half-written cache from an interrupted update is the #1 cause of "plugin won't load". Clear it. Your character, bank, and progress live on Jagex's servers, not in these folders, so deleting them is safe — you'll simply re-download them on next launch:

🗑️ Cache locations on macOS

  • ~/Library/Caches/Jagex Launcher/ — delete this folder.
  • ~/Library/Application Support/Jagex Launcher/ — you can remove the cache subfolder here without losing your account.
  • ~/Library/Application Support/Old School RuneScape/ — the game's own cache; safe to clear if the client freezes after login.

Order matters: clear the launcher cache first, relaunch, and only if the hang persists move to the game cache. The launcher cache is smaller and more often the culprit; the game cache is larger and slower to rebuild, so save it for when the launcher cache alone doesn't fix things.

⑨ Reinstall as a native arm64 app

If the hang survives a cache wipe, the app binary itself may be the wrong architecture (an old Intel download, or a copy dragged from another Mac):

  • Drag the Jagex Launcher to Trash, then empty it.
  • Re-download the macOS (Apple Silicon) installer directly from the official Jagex site — not a mirrored or old Intel copy.
  • Install, un-quarantine (Section 3.5), and launch from a native (non-Rosetta) Terminal.
🔋 Why this fixes the "beachball of death"

The plugin loader fetches a small native component on first run. On a mismatched architecture that component never initializes, so the UI thread blocks forever waiting on it. A clean arm64 reinstall drops in the correct component and the spinner finally completes. This is the same root cause as the Java-architecture mismatch in Section 2 — the binary and its native dependency finally agree on architecture.

5. 📡 Random Disconnects on macOS

Getting "You have been disconnected" mid-boss with a stable password is rarely the account — it's macOS quietly dropping your session. The mobile background-disconnect fix shares the same root causes (sleep + network), but on a Mac the usual culprits are different and easier to pin down with a couple of Terminal tests.

⑩ Sleep and Wi-Fi power saving

  • Lid close = instant drop. OSRS does not survive macOS sleep. Use Clamshell mode with an external display + power, or set "Prevent sleep" via caffeinate -s in Terminal while you play.
  • Wi-Fi "disconnect on sleep" in System Settings → Wi-Fi → Details → Wake for network access can flap your connection. Keep the Mac awake.
  • Low Power Mode (battery menu) can throttle the Wi-Fi radio under load. Disable it during long sessions.

The lid-close drop is the most common "random" disconnect Mac players report, because it often happens after they step away for a minute thinking the game will idle. OSRS's connection times out the moment the OS suspends networking, and when you return and open the lid, you're already booted. caffeinate -s is the one-line insurance: it tells macOS to never sleep while that Terminal command runs.

⑪ DNS, IPv6, and VPN

🌐 Network hardening for OSRS

  • Set DNS to 1.1.1.1 (Cloudflare) or 8.8.8.8 (Google) in System Settings → Wi-Fi → Details → DNS. macOS default resolvers occasionally black-hole the login handshake.
  • If you're on IPv6-only or dual-stack, try disabling IPv6 temporarily to rule out a flaky v6 route to the game servers.
  • Using a VPN? Many OSRS disconnects are VPN reconnections. See our VPN login-blocked fix — Jagex can also flag VPN IPs as suspicious and boot you.

DNS is the quiet hero here. The OSRS client resolves the login and game servers by name; if your ISP's resolver intermittently fails or rate-limits, you get mid-session drops that look like server issues but are entirely local. Public resolvers like 1.1.1.1 are fast and reliable, and switching is a two-minute change that fixes a surprising number of "random" disconnects.

💡 Quick test

Open Terminal and ping -c 20 1.1.1.1 while you'd normally disconnect. If you see spikes or timeouts exactly when OSRS drops, your network — not Jagex — is the problem. Our home router troubleshooting guide covers the router side (2.4GHz vs 5GHz, NAT timeout, and UPnP).

6. 🔐 macOS Permissions & Gatekeeper

macOS privacy controls can silently break the launcher even after a clean install. If login fails with vague errors or the client launches but can't reach the network, walk this list — these are the settings that bite Mac players specifically, because they're unique to Apple's privacy model.

  • Full Disk Access (System Settings → Privacy & Security): grant it to the Jagex Launcher so it can read its own cache and write tokens. Not strictly required, but it resolves the weirdest "permission denied" hangs.
  • Network / Firewall: if you run the built-in firewall, ensure it isn't blocking outgoing connections from the launcher. Set it to "Allow incoming connections" for the app, or temporarily disable to test.
  • Screen Time → Content & Privacy: a managed Mac (work/school) may block the launcher's network calls. Turn off Content Restrictions to test.
  • Gatekeeper: after any macOS update, re-run the xattr -dr un-quarantine command from Section 3.5 — updates can re-stamp the flag.

These four settings are the ones that produce the most confusing failures, because they don't throw a clear "blocked" dialog — they let the app open, then quietly prevent it from doing its job. If you've done everything in Sections 2–5 and still can't log in, one of these privacy controls is almost certainly the last blocker. The firewall one is especially sneaky: macOS can allow the launcher to launch but silently drop its outbound login handshake, which again reads as "Failed to login."

Final Mac checklist before contacting support

  • Native arm64 Java (Section 2) ✅
  • Quarantine flag removed (Section 3.5) ✅
  • Keychain Jagex tokens cleared (Section 3.4) ✅
  • Cache wiped (Section 4.8) ✅
  • DNS set to 1.1.1.1, Mac kept awake (Section 5) ✅
  • Full Disk Access + firewall checked (Section 6) ✅

8. ❓ FAQ — OSRS on Mac

Does OSRS run natively on Apple Silicon, or only through Rosetta?

The Jagex Launcher and the Old School RuneScape client both ship native arm64 builds, so an M1/M2/M3/M4 Mac should run them without Rosetta. The hang almost always comes from a leftover x86_64 Java or an old Intel installer lingering on the system. Follow Section 2 to confirm and fix the architecture. If file "$(/usr/libexec/java_home)/bin/java" reports x86_64, that's your culprit.

Why does "Failed to login" appear only on my Mac but not on my phone?

Because the two clients store separate login tokens. macOS Keychain may be replaying a dead session token from before a password reset, while your phone already re-authenticated. Clearing the Jagex entries from Keychain (Section 3.4) forces a clean login on the Mac. The phone and the Mac do not share a token store, so fixing one never fixes the other.

Is it safe to delete the Application Support / Caches folders?

Yes. Your character, bank, and levels live on Jagex's servers, not your Mac. Deleting ~/Library/Caches and the launcher's support folder only removes local cached files; you'll simply re-download them on next launch and log back into the same account. You will not lose a single item. This is the safest and most effective fix for a frozen plugin.

My Mac connects to Wi-Fi but OSRS still drops — what now?

Check DNS first (set to 1.1.1.1), then test with the Mac kept fully awake via caffeinate. If disconnects line up with VPN reconnects, the VPN is the cause. Our router guide and VPN guide cover the rest. A ping -c 20 1.1.1.1 that shows timeouts at the exact moment you drop confirms it's the network, not Jagex.

Should I just use the Steam version on Mac instead?

If the standalone Jagex Launcher keeps misbehaving, the Steam client on macOS is a valid alternative — but remember a Steam-linked account must log in via the Steam button everywhere, including on Mac. The underlying architecture rules in Section 2 still apply to Steam's macOS build, and you'll still need the correct arm64 Java. Switching clients doesn't bypass the architecture or token fixes.

Why does the launcher work for weeks then suddenly hang after a macOS update?

macOS updates frequently re-stamp the Gatekeeper quarantine flag on installed apps and can reset privacy permissions like Full Disk Access. The launcher was fine until the update re-quarantined it and silently blocked its network handshake. Re-run sudo xattr -dr com.apple.quarantine and re-grant permissions after any major macOS update — that single step resolves the post-update hang in most cases.

Can a VPN or corporate proxy cause "Failed to login" on Mac?

Yes. A VPN or proxy that intercepts TLS can break the login handshake, and Jagex may also flag shared VPN IPs as suspicious and boot you mid-session. If you're on a corporate or school network, try a direct connection first. Our VPN login-blocked fix walks through whitelisting and split-tunnel settings that keep OSRS stable while the VPN stays on.

How do I know if my Java is the wrong architecture?

Run file "$(/usr/libexec/java_home)/bin/java" in Terminal. If the output says x86_64 on an Apple Silicon Mac, you have the wrong (Intel) Java and it's running under Rosetta — the classic silent-hang cause. The fix is to install an arm64 (aarch64) build of Eclipse Temurin or Azul Zulu and point JAVA_HOME at it, as shown in Section 2.

Will resetting my Mac or reinstalling macOS fix OSRS login?

It will, but it's drastic overkill. A full reset wipes the stale Keychain tokens, the wrong Java, and the quarantine flag all at once — which is exactly why it "fixes" the problem. But you can achieve the same result in ten minutes with Sections 2–6 (correct Java, clear Keychain, un-quarantine, wipe cache, fix permissions) without losing anything else. Reserve a reinstall for when nothing else works.

Do these fixes apply to the Old School RuneScape app from the App Store too?

The architecture, Keychain, and quarantine fixes apply to every macOS build of the client, including any App Store version. The App Store version manages its own updates, so the post-update re-quarantine issue is less common there — but the Java architecture mismatch and the stale-token "Failed to login" still apply, because those are about your system environment, not the delivery channel. Walk Sections 2–3 first regardless of where you got the app.
