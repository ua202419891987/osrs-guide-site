1. 🎨 What 117HD Actually Does (and Why It's Fragile)

117HD is a community HD renderer for RuneLite that replaces the flat 2007-style look with real-time lighting, shadows, and PBR-ish materials. Under the hood it compiles custom OpenGL/GLSL shaders on your GPU every time it starts — and that shader compilation is where most crashes are born. Unlike the plain GPU plugin, 117HD ships its own lighting pipeline, so generic "just reinstall the GPU plugin" advice rarely fixes it. If you're setting up fresh, start from our RuneLite setup guide so the base client is correct first.

🎯 The 117HD Fragility Map

  • Shader compile — needs a healthy, modern GPU driver. A half-installed or beta driver fails here → "Graphics initialization failed".
  • Texture / shader cache — grows with playtime and VRAM pressure; corruption here causes freezes and artifacting.
  • Renderer mode — 117HD can run on the Default (new) or Legacy pipeline; picking wrong for your card causes tearing or a black screen.
  • Co-existence with GPU plugin — enabling both 3D pipelines at once double-binds the OpenGL context and crashes the client.

The good news: 117HD crashes are almost always configuration or driver issues, not hardware death. Every fix below keeps your account, your settings, and your cache (where safe). Mobile players hitting a black screen should also see our Android black-screen fix — the causes differ but the "force a clean GPU init" logic is similar.

💡 First, isolate 117HD from the rest

Before deep fixes, temporarily disable the 117HD plugin (and the GPU plugin) and launch with the normal client renderer. If the client is now stable, you've confirmed 117HD is the culprit and can work the sections below with confidence instead of blindly reinstalling RuneLite.

2. 🖥️ "Graphics Initialization Failed" / Black Screen on Launch

This is the most frightening 117HD error: the client opens, the 117HD plugin tries to build its shader program, and instead of a world you get a black screen, a frozen window, or a popup reading "Graphics initialization failed". It means the GPU/OpenGL context could not be created or the shader failed to compile.

② Fix A — Confirm the GPU plugin isn't fighting 117HD

Single renderer rule

  • Open RuneLite → Configuration (wrench icon) → find the GPU plugin. If it's enabled, turn it off while 117HD is on.
  • In 117HD's own settings, the "Renderer" option should be set to Default (OpenGL) for modern cards — do not also flip the separate GPU plugin's "Enable GPU" on.
  • Two 3D renderers binding one OpenGL context = instant crash on most systems.

③ Fix B — Clear the corrupted 117HD shader cache

Wipe the cache, keep your account

  • Close RuneLite fully (check the system tray).
  • Open your RuneLite folder: %USERPROFILE%\.runelite\ on Windows, ~/.runelite/ on macOS/Linux.
  • Delete the 117hd subfolder (or the shader_cache / materials_cache inside it). This forces a clean recompile next launch.
  • Reopen RuneLite. First launch will stutter for 10–30s while shaders rebuild — that's normal, not a crash.

④ Fix C — Verify the driver actually loads

  • Open dxdiag (Windows) or your GPU control panel and confirm the dedicated GPU is detected, not "Microsoft Basic Display Adapter".
  • If you see the basic adapter, your real driver didn't install — go to Section 6.
🚨 Don't "just update" on a black screen

A blind driver update on a already-fragile setup can swap one failure for another. First confirm which driver version was stable (check your OS update history), then either roll back (Section 6) or do a clean install of a known-good version. DDU (Display Driver Uninstaller) on Windows gives a truly clean slate if normal uninstall leaves residue.

3. 📉 FPS Crashes & Sudden Freezes (VRAM & Shader Cache)

A different failure mode: the game runs, then FPS suddenly collapses from 60 to single digits, the screen freezes for a few seconds, or the client hard-crashes in busy areas (GE, Raids, large drops). This is rarely the shader compile — it's VRAM exhaustion and a bloated shader/texture cache.

⑤ How much VRAM 117HD actually wants

Scene / Area117HD VRAM EstimateRisk on a 2 GB Card
Quiet skilling (woods, mines)~1.0–1.5 GBLow
Grand Exchange / Varrock~2.0–2.8 GBHigh — FPS cliff likely
Raids / large boss masses~2.5–4.0 GBVery high — crash likely
With HD texture pack add-on+1.5–3 GB on topAlmost always crashes <4 GB

⑥ Cut VRAM pressure without losing the look

Step 1 — Cap the 117HD texture cache

In 117HD settings, lower "Texture resolution" and set a max cache size (e.g., 1024 MB) so it can't balloon. Disable the separate HD texture pack if you're on a 2–4 GB card.

Step 2 — Disable the heaviest effects first

  • Turn off shadows and water reflections — they're the two biggest VRAM/FPS hogs and the usual trigger for freezes in crowds.
  • Keep lighting and normals; the scene still looks HD but uses far less memory.

Step 3 — Periodic cache reset

If freezes return after weeks of play, the shader cache has fragmented. Repeat the cache delete from Section 2, Fix B. A 30-second rebuild beats a daily crash.

🔋 Laptops: force the dedicated GPU

Many laptops silently run RuneLite on the integrated GPU (Intel/AMD iGPU) with 128–512 MB shared memory — instant 117HD death. In Windows Graphics Settings → "High performance" for RuneLite.exe, and in the NVIDIA/AMD control panel set the discrete GPU as preferred. For on-the-go settings, our best-settings guide covers the mobile side of the same problem.

4. 🧩 Screen Tearing & Stutter (VSync & Renderers)

Screen tearing — horizontal slices of the image misaligned, especially when the camera whips around in a raid — is a vsync/renderer mismatch, not a crash. It's annoying and can cost you a pixel-perfect tick, so fix it.

⑦ The vsync decision

  • Enable vsync in 117HD if your monitor is 60 Hz and you see tearing. It caps FPS to the refresh rate and eliminates the tear.
  • Disable vsync if you have a 120/144 Hz panel and want higher FPS — but then use your GPU driver's "Fast Sync" / "Enhanced Sync" instead so you keep smoothness without the tear.
  • Don't enable vsync in both 117HD and the GPU plugin — double vsync causes stutter, not smoothness.

⑧ Renderer mismatch causes stutter too

⚙️ Match the pipeline to the card

If you're on the Legacy renderer (Section 5) but your driver expects the new pipeline, you'll get micro-stutters on camera moves. Switch to Default for any GPU from the last ~6 years, and the tearing usually resolves with vsync on.

💡 "Stutter only in busy areas"

That's VRAM thrashing, not vsync — jump back to Section 3 and cap the cache. Tearing is everywhere; stutter-only-when-crowded is a memory problem.

5. ⚖️ Legacy vs Default Renderer — Which in 2026

117HD exposes a Renderer dropdown: typically Default (the modern OpenGL pipeline) and Legacy (the older path). Players confuse this with the GPU plugin's own toggle, but within 117HD it controls which internal draw path 117HD uses. Picking wrong is a top cause of "black screen on my old laptop" vs "why is my 4090 capped at 30 FPS".

⑨ Decision table

Your GPUPickWhy
NVIDIA GTX 10-series or newer / RTXDefaultModern OpenGL, best FPS & effects
AMD RX 400-series or newerDefaultFull shader support
Intel Arc / recent Iris XeDefaultSupported on current drivers
Older than ~2015 / weak iGPU onlyLegacy (or drop 117HD)New pipeline may fail to init; Legacy is more forgiving
macOS with known GL issuesLegacy first, test DefaultApple's GL stack is finicky

⑩ How to switch safely

  • Disable 117HD, restart RuneLite, then re-enable it with the Renderer set to your choice — changing it live can leave a half-built context.
  • After switching to Default on a capable card, you should see higher and steadier FPS plus all lighting effects. If FPS drops or it blacks out, fall back to Legacy.
  • Legacy trades some effect quality for stability — acceptable on ancient hardware where Default simply won't initialize.
⚠️ It's not the GPU plugin toggle

Repeat after me: within 117HD, "Renderer = Default/Legacy" is internal to 117HD. The separate RuneLite GPU plugin should stay off while 117HD runs (Section 2, Fix A). Mixing the two mental models is why so many players can't get a stable HD client.

6. 🔧 Driver Update Broke 117HD — Roll Back

"It worked yesterday, then Windows/GeForce Experience updated my driver and now 117HD crashes." This is extremely common: a new driver revises the OpenGL behavior 117HD's shaders depend on, or introduces a regression specific to your GPU. The fix is to return to the last known-good driver.

⑪ Roll back on Windows

Device Manager rollback

  • Win+X → Device Manager → Display adapters → right-click your GPU → Properties → Driver → Roll Back Driver.
  • If the button is greyed out (no previous driver stored), download the prior version from NVIDIA/AMD/Intel's site and do a clean install.

Clean install with DDU (nuclear option)

  • Download DDU and your target driver version first.
  • Boot to Safe Mode, run DDU to wipe all GPU driver traces, reboot, then install the known-good driver only.
  • Reopen RuneLite — the "graphics initialization failed" usually clears because the shader now compiles against a stable GL stack.

⑫ Avoid the next break

  • On Windows, pause automatic GPU driver updates (Settings → Windows Update → optional driver updates) so a silent push can't break 117HD mid-progress.
  • Before any driver update, note the version that's stable. If the new one breaks 117HD, you now have an instant rollback target.
  • Prefer WHQL / Studio / stable branches over "Game Ready Beta" or fresh-release drivers for a renderer as shader-sensitive as 117HD.
💡 Linux/macOS note

On Linux with Mesa, a mesa update can similarly break 117HD — pin or downgrade mesa/libgl to recover. On macOS, stick to the Legacy renderer (Section 5) and keep the OS reasonably current; 117HD's Mac support trails Windows by design.

7. 🚑 5-Minute Stability Checklist

When 117HD misbehaves, run this in order. Most crashes resolve by Step 3.

→ Step 1: Disable the separate GPU plugin — 117HD must be the only 3D renderer. (§2 Fix A)
→ Step 2: Delete the 117hd shader/texture cache in .runelite/ and relaunch. (§2 Fix B)
→ Step 3: Set 117HD Renderer to Default (modern GPU) or Legacy (old GPU). (§5)
→ Step 4: Cap texture cache + disable shadows/reflections if FPS collapses in crowds. (§3)
→ Step 5: If it broke after an update, roll back the GPU driver to the last stable version. (§6)
📸 Capture the error before you fix

Snap a screenshot or copy the exact error text ("Graphics initialization failed", the GL version string, your GPU model). If you later need the generic GPU-plugin guide or a support thread, that detail gets you an answer in one reply instead of five.

9. ❓ FAQ — 117HD Crashes

Will disabling 117HD delete my settings or my account?

No. Your account lives on Jagex's servers. 117HD settings are stored in the RuneLite .runelite config; toggling the plugin off and on keeps them. Only deleting the 117hd cache folder (Section 2) resets visuals — and even that rebuilds automatically.

Can I run 117HD and the GPU plugin together for "extra" quality?

No — and this is the #1 mistake. Both try to own the OpenGL 3D context; running both causes the crash or black screen described in §2. Keep 117HD on and the GPU plugin off. (The GPU plugin alone is a separate, lighter HD path covered in our GPU plugin crash fix.)

My FPS is fine solo but craters in a 100-man mass — why?

VRAM. Big crowds load far more models, textures, and lighting samples, pushing 117HD past your card's memory. Cap the texture cache and drop shadows/reflections (§3) and the cliff softens. On a <4 GB card, consider Legacy or the GPU plugin instead of 117HD for mass events.

After a Windows update 117HD won't even open — driver or RuneLite?

Usually the driver. Windows Update often slips in a generic or newer GPU driver that breaks 117HD's shaders. Roll back to your known-good version (§6) and pause auto driver updates. If RuneLite itself updated, the 117HD plugin may need a matching update — check the plugin hub for a 117HD revision.

Is Legacy "worse" than Default, or just different?

Legacy is the older draw path: more forgiving on ancient GPUs but with fewer/older effects and often lower peak FPS on capable hardware. On any GPU from the last ~6 years, Default looks better and runs faster. Use Legacy only when Default fails to initialize (§5).
